# Cryptographic Provenance & Attestation Verification

ByteBuddhi builds and releases are cryptographically attested using **GitHub Artifact Attestations** powered by Sigstore. This enables external users and security auditors to verify that released binaries and packages originated from this repository, were generated by our trusted workflow, and have not been tampered with.

---

## Checksum vs. Provenance Verification

It is critical to distinguish between these two layers of release verification:

1. **Checksum Verification (SHA-256):**
   - Proves **Integrity**: confirms that the file downloaded matches the hash listed in `SHA256SUMS.txt`.
   - Does *not* prove authenticity: an attacker who compromises the download server could replace both the file and the hash list.

2. **Provenance Attestation Verification:**
   - Proves **Authenticity & Supply Chain Origin**: confirms via Sigstore's transparency log that the artifact was compiled inside GitHub Actions from the exact repository commit and workflow run.
   - Cryptographically bound to GitHub's OIDC issuer.

## Verifying Attestations with GitHub CLI

Ensure you have `gh` CLI version `2.49.0` or later installed.

### 1. Python Wheel / Tarball Verification

```bash
gh attestation verify dist/bytebuddhi-0.1.3-py3-none-any.whl \
  --owner Navin45 \
  --repo bytebuddhi \
  --signer-workflow Navin45/bytebuddhi/.github/workflows/release.yml
```

Expected output:
```
Loaded digest sha256:... for dist/bytebuddhi-0.1.3-py3-none-any.whl
Loaded 1 attestation from GitHub API
✓ Verification succeeded!

[Attestation details]
Repository:   Navin45/bytebuddhi
Workflow:     .github/workflows/release.yml
Runner:       GitHub-hosted
Target Tag:   v0.1.3
```

### 2. Desktop Installers Verification

#### Windows Installer (.exe / .zip)
```powershell
gh attestation verify desktop/dist/ByteBuddhi-Setup-0.1.3.exe `
  --owner Navin45 `
  --repo bytebuddhi `
  --signer-workflow Navin45/bytebuddhi/.github/workflows/release.yml
```

#### macOS Installer (.dmg)
```bash
gh attestation verify desktop/dist/ByteBuddhi-0.1.3-arm64.dmg \
  --owner Navin45 \
  --repo bytebuddhi \
  --signer-workflow Navin45/bytebuddhi/.github/workflows/release.yml
```

#### Linux Package (.AppImage / .deb)
```bash
gh attestation verify desktop/dist/ByteBuddhi-0.1.3.AppImage \
  --owner Navin45 \
  --repo bytebuddhi \
  --signer-workflow Navin45/bytebuddhi/.github/workflows/release.yml
```

## What the Attestation Proves

When verification succeeds, the cryptographic certificate guarantees:

1. **Expected Repository:** The binary was produced by `Navin45/bytebuddhi`.
2. **Expected Workflow:** The build ran in `.github/workflows/release.yml`.
3. **Expected Identity:** Built on GitHub Actions infrastructure with immutable identity tokens.
4. **Digest Match:** The SHA-256 digest of the downloaded file exactly matches the subject of the signed in-toto statement.
